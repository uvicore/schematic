# 2026-08-27

## Stub + skill guidance for the new `pool` block and Snowflake defaults (framework 0.4.11)

- **Intent:** Framework 0.4.11 added a per-connection `pool` config block and made Snowflake
  connections survive past their ~4h master token. Generated apps and their guidance had to reflect
  the new app-author surface.

- **Changed:**
  - `acme/appstub/config/database.py` — commented `pool` block on the MySQL example (with the
    `options` = driver vs `pool` = engine distinction, the key list, and the "only pre_ping is
    defaulted" note), and a note on the Snowflake example explaining that uvicore now defaults
    `client_session_keep_alive` + a 900s heartbeat and treats expired-token codes as disconnects —
    so those keys are there to OVERRIDE, not to enable. Left commented so a fresh app's behavior is
    unchanged; the stub is where an app author actually reads this.
  - `.claude/skills/uvicore-database/SKILL.md` — §5 Connections now distinguishes `options` (driver)
    from `pool` (engine pool), lists the keys, warns off `size`/`max_overflow` on sqlite
    `':memory:'`, and states that Snowflake session survival is handled by the framework.

- **Files:** `acme/appstub/config/database.py`,
  `.claude/skills/uvicore-database/SKILL.md`

- **Related:** framework `adr/0009-configurable-engine-pooling-and-snowflake-session-resilience.md`
